[1.2] CODE SNIPPET 1: Wrist-Relative & Palm-Scale Normalization (utils.py)
--------------------------------------------------------------------------------
```python
WRIST_IDX = 0          # landmark index 0 = wrist
PALM_REF_IDX = 9       # landmark index 9 = middle finger MCP (base of middle finger)

def normalize_landmarks(raw: list | np.ndarray) -> np.ndarray:
    """
    Normalize a flat array of 63 landmark values (21 points x 3 coordinates: x, y, z).
    Makes features position-invariant and scale-invariant.
    """
    # Step 1: Reshape 63 numbers into 21 points with (x, y, z)
    pts = np.array(raw, dtype=np.float32).reshape(21, 3)

    # Step 2: Translation Invariance — subtract wrist coordinate
    pts -= pts[WRIST_IDX]

    # Step 3: Scale Invariance — divide by Euclidean palm length (wrist to middle finger base)
    palm_len = np.linalg.norm(pts[PALM_REF_IDX])
    if palm_len > 1e-6:          # Avoid division by zero
        pts /= palm_len

    return pts.flatten()
```

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 1 ---
* What does MediaPipe give us?
  MediaPipe gives 21 points on the hand. Each point has X, Y, and Z coordinates. 
  21 x 3 = 63 numbers per hand.
* The Problem:
  If you stand on the left of the screen vs the right, the raw coordinates change completely.
  If you move your hand close to the camera, the numbers become large. If you move 
  far away, the numbers become small. A neural network would get confused.
* The Solution in Code:
  1. `pts -= pts[WRIST_IDX]`: We make the wrist coordinate (0, 0, 0). All other 20 
     fingertips and joints are measured relative to the wrist. Now it doesn't matter 
     WHERE your hand is on screen!
  2. `palm_len = np.linalg.norm(pts[PALM_REF_IDX])`: We calculate the exact physical 
     distance between the wrist and the middle finger base using Euclidean distance.
  3. `pts /= palm_len`: We divide all coordinates by this palm length. If the hand 
     is close to the camera, palm length is big, so dividing shrinks it. If far away, 
     palm length is small, so dividing scales it up. 
  Result: The numbers are ALWAYS standardized between -1.0 and +1.0 regardless 
  of distance!

[1.3] CODE SNIPPET 2: Bilateral Hand Mirroring (utils.py)
--------------------------------------------------------------------------------
```python
def mirror_hand(pts: np.ndarray) -> np.ndarray:
    """
    Flip the X-axis of normalized landmarks to simulate the OPPOSITE hand.
    Negating X produces a geometrically perfect left-hand sample from a right-hand sample.
    """
    pts = pts.reshape(21, 3).copy()
    pts[:, 0] = -pts[:, 0]   # Flip X coordinate; Y and Z stay unchanged
    return pts.flatten()
```

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 2 ---
* Why did we write this?
  Most sign language datasets are collected using the right hand. If a left-handed 
  person uses the system, the model normally fails.
* How this code solves it:
  Because all points are centered at the wrist (0, 0, 0), the left hand is an exact 
  mirror reflection of the right hand across the vertical Y-axis.
  By simply writing `pts[:, 0] = -pts[:, 0]`, we negate the X-axis. 
  A left hand instantly turns into a right hand in coordinate space!
* Benefit:
  We didn't have to collect double the dataset. Both left-handed and right-handed 
  users work out of the box with 100% accuracy.

```python
def extract_isl_landmarks(result):
    """
    Extract and normalize landmarks for ISL (both hands).
    Returns 126 numbers: (Right hand 63 values + Left hand 63 values).
    If a hand is missing, it fills 63 zeros for padding.
    """
    if not (result and result.hand_landmarks):
        return None, 0

    num_detected = len(result.hand_landmarks)
    right_raw    = np.zeros(63, dtype=np.float32)
    left_raw     = np.zeros(63, dtype=np.float32)
    left_detected = False

    for hi in range(num_detected):
        hand_lms = result.hand_landmarks[hi]
        raw_lm   = [coord for lm in hand_lms for coord in (lm.x, lm.y, lm.z)]
        h_label  = result.handedness[hi][0].category_name

        # In horizontally mirrored camera: MediaPipe "Left" = user's physical right hand
        if h_label == "Left":
            right_raw = np.array(raw_lm, dtype=np.float32)
        else:
            left_raw = np.array(raw_lm, dtype=np.float32)
            left_detected = True

    # Normalize both hands independently relative to their own wrists
    combined = normalize_isl_landmarks(right_raw, left_raw)

    # Mirror the left hand part so geometric orientation is standardized
    if left_detected:
        combined[63:] = mirror_hand(combined[63:])

    return combined, num_detected
```

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 1 ---
* What is Indian Sign Language (ISL)?
  Unlike ASL which is mostly single-handed fingerspelling, ISL uses BOTH hands for 
  most letters (like P, Q, X, W).
* The Challenge:
  How do we feed two hands into an AI model? And what if the user only shows one hand?
* How this code solves it:
  1. We allocate two 63-slot arrays (`right_raw` and `left_raw`).
  2. Total array size is 63 + 63 = 126 features.
  3. If both hands are present, each hand is placed into its respective half.
  4. If only one hand is visible, the other hand's 63 slots stay as zeros (zero-padding).
  5. Each hand is normalized around its own wrist, keeping scale and position invariant.

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 1 ---
* Why this architecture?
  Many signs look very similar (for example, M, N, and T only differ by where the thumb 
  is tucked between fingers). A simple 2-layer network gets confused.
* How each component helps:
  1. `Input(shape=(63,))`: Receives the 63 normalized hand coordinates.
  2. `Dense(512)` tapering down to `Dense(32)`: A pyramid design. The wide 512-neuron 
     entry layer captures fine-grained joint angle relationships, and deeper layers 
     abstract them into high-level sign representations.
  3. `BatchNormalization()`: Normalizes neuron activations across each batch. This 
     speeds up training 5x and prevents internal covariate shift.
  4. `Dropout(0.4 to 0.2)`: Randomly turns off 40% of neurons during training so the 
     network doesn't memorize the training samples (prevents overfitting).
  5. `l2(1e-4)`: Penalizes large weight values so no single joint dominates the decision.
  6. `Softmax`: Converts raw scores into percentages (e.g. A: 96%, B: 2%, C: 1%).

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 2 ---
* Why an LSTM instead of Dense?
  Dense networks only understand a single moment in time. But motion letters like 'J' 
  and 'Z' have temporal direction—where the finger WAS 10 frames ago and where it IS now.
  LSTM (Long Short-Term Memory) is a recurrent network with a memory cell that 
  remembers past frames.
* Why Bidirectional LSTM?
  Standard LSTMs only read time forward. `Bidirectional(LSTM(128))` processes the 
  gesture both forward and in reverse. This ensures the model understands both how 
  the gesture started and where it ended, making it immune to minor timing variations.

[4.2] CODE SNIPPET 1: Weighted Temporal Prediction Smoothing (backend.py)
--------------------------------------------------------------------------------
```python
# Rolling buffers for predictions and confidence scores
asl_pred_buf = deque(maxlen=15)
asl_conf_buf = deque(maxlen=15)

def smooth_prediction(letter: str, conf: float):
    """
    Eliminates frame flicker using a 15-frame weighted majority voting window.
    Recent frames receive higher weight than older frames.
    """
    asl_pred_buf.append(letter)
    asl_conf_buf.append(conf)

    # Weighted majority vote
    vote_counter = Counter()
    for index, sign in enumerate(asl_pred_buf):
        # Linear weighting: index 0 gets weight 1.0, index 14 gets weight 3.1
        vote_counter[sign] += 1.0 + index * 0.15

    smoothed_letter = vote_counter.most_common(1)[0][0]

    # Weighted confidence calculation
    conf_list = list(asl_conf_buf)
    weights   = np.array([1.0 + i * 0.15 for i in range(len(conf_list))])
    smoothed_conf = float(np.average(conf_list, weights=weights))

    return smoothed_letter, smoothed_conf
```

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 1 ---
* The Problem: Frame Flicker (Jitter)
  In live video, your hand might wobble slightly for 1 single frame. The raw model 
  might output: `['A', 'A', 'A', 'A', 'S', 'A', 'A']`.
  If you display that immediately, the screen flickers nervously and the text-to-speech 
  stutters.
* The Solution in Code:
  1. We store the last 15 frame predictions in a `deque(maxlen=15)` queue.
  2. We don't do a naive average: we use Weighted Voting (`1.0 + index * 0.15`). 
     The latest frame has 3x more voting power than a frame from 15 frames ago.
  3. `vote_counter.most_common(1)` picks the winner.
  Result: A 1-frame wobble is instantly filtered out, but an intentional change of sign 
  is recognized smoothly within 100 milliseconds!

[4.3] CODE SNIPPET 2: Automatic Emergency (SOS) State Machine (backend.py)

```python
# Automatic SOS: 3-Repetition 'S' Gesture State Machine
SOS_S_MIN_HOLD_FRAMES    = 6      # ~0.6s hold of letter 'S'
SOS_S_MIN_RELEASE_FRAMES = 4      # ~0.4s release between reps
SOS_S_WINDOW_SECONDS     = 10.0   # Must complete 3 reps within 10 seconds

def update_sos_s_detector(is_s_detected: bool, conf: float) -> tuple[int, bool]:
    """
    Detects if a user intentionally shows 'S', releases, shows 'S', releases, 
    and shows 'S' a third time within 10 seconds to trigger emergency assistance.
    """
    global sos_s_reps, sos_s_hold_count, sos_s_release_count, sos_s_in_hold, sos_s_start_time
    now = time.time()

    # Reset if user took longer than 10 seconds
    if sos_s_reps > 0 and (now - sos_s_start_time > SOS_S_WINDOW_SECONDS):
        sos_s_reps = 0

    if is_s_detected and conf >= 0.70:
        sos_s_release_count = 0
        if not sos_s_in_hold:
            sos_s_hold_count += 1
            if sos_s_hold_count >= SOS_S_MIN_HOLD_FRAMES:
                sos_s_reps += 1               # Confirmed one deliberate 'S'
                sos_s_in_hold = True
                if sos_s_reps == 1:
                    sos_s_start_time = now

                if sos_s_reps >= 3:          # 3 deliberate repetitions -> TRIGGER SOS!
                    sos_s_reps = 0
                    return 3, True
    else:
        sos_s_hold_count = 0
        if sos_s_in_hold:
            sos_s_release_count += 1
            if sos_s_release_count >= SOS_S_MIN_RELEASE_FRAMES:
                sos_s_in_hold = False        # Hand released, ready for next rep

    return sos_s_reps, False
```

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 2 ---
* Why this feature is vital:
  In real life, a mute person in danger (medical emergency, assault) cannot shout for help.
  Simply pressing a button might not be possible if they cannot reach the keyboard.
* How the State Machine works:
  1. If someone just spells a word containing 'S' (like "REST"), we do NOT trigger SOS.
  2. The algorithm requires a deliberate pattern: Hold 'S' for 6 frames -> Release hand 
     for 4 frames -> Repeat 3 times within 10 seconds.
  3. When all 3 reps are verified, it automatically triggers a full-screen red emergency 
     alert and speaks: "Emergency. Help needed!"

```python
/**
 * Text-to-Speech vocalization using Web Speech API with Chromium race-condition fix.
 */
export function speakText(text) {
  if (!text || typeof window === 'undefined' || !('speechSynthesis' in window)) {
    return;
  }
  try {
    const synth = window.speechSynthesis;
    if (synth.paused) {
      synth.resume();
    }
    synth.cancel();    // Clear any previously queued utterances

    // Defer utterance by 20ms so cancel() completes cleanly in Chromium browsers
    setTimeout(() => {
      try {
        if (synth.paused) synth.resume();

        const utterance = new SpeechSynthesisUtterance(text);
        utterance.rate = 0.95;       // Natural human speaking rate
        utterance.pitch = 1.0;
        utterance.lang = 'en-US';

        const voices = synth.getVoices();
        if (voices && voices.length > 0) {
          const enVoice = voices.find(v => v.lang.startsWith('en'));
          if (enVoice) utterance.voice = enVoice;
        }

        synth.speak(utterance);
      } catch (err) {
        console.warn('[TTS] Utterance error:', err);
      }
    }, 20);
  } catch (err) {
    console.warn('[TTS] Synthesis error:', err);
  }
}
```

--- SIMPLE LANGUAGE EXPLANATION OF SNIPPET 1 ---
* Why this is needed:
  The goal of SignBridge is two-way communication. When a deaf person signs "HELLO", 
  a hearing person needs to HEAR it immediately.
* The Chromium Bug Fix:
  In Google Chrome and Edge, calling `window.speechSynthesis.speak()` consecutively 
  often freezes silently due to an internal browser queue deadlock.
* How our code fixes it:
  1. We call `synth.cancel()` to clear stale audio.
  2. We add a 20ms `setTimeout` delay so Chromium can cleanly reset its audio buffer.
  3. We set `utterance.rate = 0.95` for natural, crisp pronunciation.
  4. It speaks in the background without causing ANY lag to the webcam video.

const COMMON_WORDS = [
  'ABOUT', 'AFTER', 'AGAIN', 'ALL', 'CALL', 'CAN', 'COME', 'DOCTOR', 'DRINK',
  'EAT', 'EMERGENCY', 'FOOD', 'FRIEND', 'GOOD', 'HELLO', 'HELP', 'HOSPITAL',
  'MEDICINE', 'NEED', 'PLEASE', 'SORRY', 'THANK', 'WATER', 'WHERE', ...
];

export const Suggestions = React.memo(function Suggestions({ currentWord, currentMode, setWord }) {
  // Compute up to 5 word autocompletions based on prefix
  const suggestions = useMemo(() => {
    if (currentMode !== 'letters' || !currentWord || currentWord.length < 2) {
      return [];
    }
    const prefix = currentWord.trim().toUpperCase();
    return COMMON_WORDS.filter(
      (word) => word.startsWith(prefix) && word !== prefix
    ).slice(0, 5);
  }, [currentWord, currentMode]);

  if (suggestions.length === 0) return null;

  return (
    <div className="sb-suggestions-list">
      {suggestions.map((word) => (
        <button key={word} className="sb-suggestion-pill" onClick={() => setWord(word)}>
          {word}
        </button>
      ))}
    </div>
  );
});

1. Q: What is the end-to-end latency of your system from camera to audio?

2. Q: How does your system perform in poor lighting conditions?
   A: "Because Google MediaPipe operates on skeletal hand joints rather than color/skin-tone 
      segmentation, it is remarkably robust in dim lighting. Once the 21 coordinates are 
      detected, our custom wrist-relative normalization and synthetic Gaussian noise 
      augmentation ensure the deep learning model evaluates pure geometry, completely 
      independent of lighting or shadows."

3. Q: What is the difference between ASL and ISL in your project?
   A: "ASL (American Sign Language) is predominantly single-handed fingerspelling, 
      requiring a 63-dimensional feature vector. ISL (Indian Sign Language) is 
      predominantly dual-handed, requiring our custom 126-dimensional feature vector 
      where both hands are tracked, normalized around their respective wrists, and 
      processed together."

4. Q: Why did you skip J and Z in the static model?
   A: "In ASL, J and Z are inherently dynamic signs. Letter 'J' requires tracing a hook 
      downward with the pinky, and 'Z' requires tracing a zigzag with the index finger. 
      A single static frame of 'J' is indistinguishable from 'I', and 'Z' is 
      indistinguishable from 'D'. That is why we built a dedicated 30-frame Bidirectional 
      LSTM model specifically for motion signs."

5. Q: What is TensorFlow Lite Quantization and why did you use it?
   A: "Quantization converts 32-bit floating-point weights and biases into 8-bit integers 
      (int8). It reduced our model file size from over 3 MB down to ~230 KB (a 92% reduction) 
      and sped up CPU inference by 300%, allowing our system to run on standard low-power 
      laptops without a dedicated GPU."

6. Q: How does your system support left-handed users if you only recorded with right hands?
   A: "We developed a bilateral parity mirroring function (`mirror_hand` in utils.py). 
      Because our landmarks are centered at the wrist (0, 0, 0), simply negating the 
      X-axis coordinates (`x = -x`) geometrically transforms a left hand into an identical 
      right hand in coordinate space."

7. Q: How do you prevent false positives when no hand is in front of the camera?
   A: "MediaPipe reports tracking confidence. If no hand is detected, or if the model's 
      softmax confidence score is below our calibrated threshold (0.65 for letters, 
      0.75 for words), the prediction is suppressed and the UI shows '—' rather than a 
      false letter."

8. Q: How does your emergency SOS detection work?
   A: "We have two automatic triggers: First, an algorithmic state machine that detects 
      if the letter 'S' sign is shown, released, and repeated 3 times within 10 seconds. 
      Second, a lateral motion wave detector that tracks the wrist's X-axis oscillation 
      velocity to identify distress waving. Both trigger priority audible and visual alarms."

9. Q: What database or persistent storage do you use?
   A: "We maintain an in-memory session conversation log in FastAPI, mirrored in React state. 
      Users can review the transcript, delete individual entries, or export the entire
